# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

POC of a 3D bilateral tower defense game (see `README.md` for the design spec). Two players share one screen; each buys units that walk straight toward the opposing base. First base destroyed loses.

Stack: **Rust + Bevy 0.18 + Avian3d 0.6**. Dev shell is a **Nix flake** (Vulkan, Wayland/X11, mold linker), loaded automatically via `direnv` when entering the directory.

Input is **gamepad-only**: two pads connect during the SideSelect screen, each player claims a side and then picks a nation (currently only Ada'Ram), and from then on every action (menu nav, unit purchase, tower placement) flows through that pad's bindings.

## Commands

```sh
cargo run                 # debug build + run
cargo run --release       # release build + run (use this for perf-sensitive testing)
cargo check               # fast type-check
cargo fmt
cargo clippy
```

For day-to-day debug iteration, prefer the aliases in `.cargo/config.toml`:

```sh
cargo runf                # debug run with Bevy dynamic_linking (much faster relinks)
cargo checkf              # check counterpart
```

`runf`/`checkf` enable `bevy/dynamic_linking` so editing our crate only relinks
our code, not the whole engine. **Never use them for release** — dynamic linking
must not ship in a distributed build, which is why it is a CLI-only alias and not
a default feature. The first `runf` is slow (it recompiles all dependencies at
`opt-level = 3`, see below); subsequent iterations are fast. Linker speed (mold +
clang) comes from `RUSTFLAGS` in `flake.nix`.

The dev profile in `Cargo.toml` is tuned for iteration: `[profile.dev.package."*"]
opt-level = 3` optimizes dependencies once (so debug Bevy is actually playable)
without slowing our own recompiles, and `debug = "line-tables-only"` trims
debuginfo to speed linking while keeping `file:line` in panic backtraces.

Unit tests live in `#[cfg(test)]` modules (pure logic/helpers — geometry, settings, seat navigation); run them with `cargo test`.

The Nix dev shell exports `LD_LIBRARY_PATH` for Vulkan/Wayland/X11. Running outside the shell will fail to find dynamic libraries — always run from within `nix develop` (or with direnv active).

### Cargo features (declared in `Cargo.toml`)

- `raytracing` (default) — pulls in `bevy_solari` for raytraced GI/shadows. Guarded everywhere with `#[cfg(feature = "raytracing")]`.
- `dlss` + `force_disable_dlss` (both default) — DLSS is *compiled in but mocked* by default so the build never needs the NVIDIA NGX SDK; at runtime `DlssRayReconstructionSupported` is absent and the menu entry stays "N/A". To run with real DLSS:
  ```sh
  cargo run --release --no-default-features --features raytracing,dlss
  ```

Bevy image features `mp3` and `jpeg` are enabled (not Cargo features of this crate but of the `bevy` dependency): `mp3` for the battle theme, `jpeg` because the Meshy-exported building/prop glTFs embed JPEG textures (without it they load untextured and Bevy logs `invalid image mime type: image/jpeg`).

### Runtime resources

- Music: `setup_music` loads `assets/music/battleTheme.mp3` at startup (path defined in `music::MUSIC_PATH`; the `mp3` Cargo feature is enabled on Bevy). The file is intentionally optional — Bevy logs a "Path not found" error and the game runs silently if it is missing.
- Persisted settings: `~/.config/attack_tower/settings.cfg` (or `$XDG_CONFIG_HOME/attack_tower/settings.cfg`). Written by `persist_settings` whenever `GameSettings` changes; loaded once at startup by `load_settings` in place of `init_resource::<GameSettings>()`.

## Architecture

The game is a Bevy `App` assembled in `src/main.rs`: the engine plugins (`DefaultPlugins`, `PhysicsPlugins::default()` — Avian, gravity disabled via `Gravity(Vec3::ZERO)` since everything is ground-bound; units are dynamic capsules driven by `LinearVelocity`, bases/towers/rocks are static colliders, all routed through the `GameLayer` collision layers in `common.rs`), the cross-module schedule skeleton, and **one `Plugin` per module** (`GamePlugin`, `SetupPlugin`, `UnitsPlugin`, `TowersPlugin`, `HealthBarPlugin`, `MusicPlugin`, `GraphicsSettingsPlugin`, `UiPlugin`), each registering its own systems and resources.

**App flow is a Bevy `States` machine.** `GameState` (Menu / Settings / SideSelect / Playing / Paused / Ended; initialized in `GamePlugin`) is transitioned via `NextState<GameState>`, applied between frames — so the new state's input system never sees the button press that caused the transition (this replaced the old per-system `!state.is_changed()` guards). The winning side is carried by the `Winner` resource, set just before entering `Ended`. A `ComputedStates`, **`InMatch`** (Playing | Paused), drives the match lifecycle: `OnEnter(InMatch)` builds the arena + initial miners, shows the HUD and grants each pad its `PlayerFocus`; `OnExit(InMatch)` hides the HUD, revokes focus and cancels tower placement. CAREFUL: `Paused → Settings → Paused` re-enters `InMatch`, so its OnEnter systems keep existence guards. Leaving `Playing` (pause or endgame) zeroes all unit velocities and **pauses Avian's `Time<Physics>`** (resumed on re-entry). `OnEnter(GameState::Menu)` runs `reset_match` (game.rs) — both "Main menu" buttons just switch state. State overlays are spawned by `OnEnter` systems and torn down with `despawn_all::<Marker>` on `OnExit`.

`Update` systems are grouped into five `SystemSet`s (`AppSet`, defined in `common.rs`, chained in `main.rs`):

1. **`AppSet::Input`** — `read_mouse_ui` first (the others consume its snapshot), then one gamepad input system per state, each gated by `run_if(in_state(..))`.
2. **`AppSet::World`** — gameplay tick. Combat lives in the chained **`CombatSet`** sub-phases (Attack → ApplyDamage → Animate → Cleanup, also in `common.rs`) so the units and towers plugins join one chain without referencing each other's systems; gameplay-only systems are gated `run_if(in_state(GameState::Playing))`.
3. **`AppSet::React`** — `check_winner`, `detect_pad_disconnect`, preset detection, torch/raytracing sync, and the two in-state overlay refreshers (pause pad-warnings, settings structural rebuild).
4. **`AppSet::Visual`** — text refreshes, healthbar billboarding, settings application. Mostly parallel; Bevy infers ordering from query conflicts.
5. **`AppSet::FrameLimit`** — `limit_fps` only. Must be last so the sleep happens after every other system.

The sets are `.chain()`ed at configuration time so mutations propagate across them within a single frame. Adding a new system means picking a plugin and a set, gating it with `run_if(in_state(..))` if state-specific, and using `.after(...)` only where there's an actual data dependency.

Modules:

- **`common.rs`** — shared types touched by every other module.
  - `Side` (`Left`/`Right`) — both a marker `Component` (on each unit/base/tower) and an enum used as a map key for `Gold`. When querying entities filter on the side component; when reading resources, pass the side enum.
  - `PlayerSlot` (`LeftBottom`/`LeftTop`/`RightBottom`/`RightTop`) — finer than `Side`. Each unit/base/tower carries both. In 1v1 only `LeftBottom`/`RightBottom` are active; in 2v2 all four. Used for per-slot gold, base Z offset, and miner ownership (so the right miner returns to the right base in 2v2).
  - Components: `Base`, `BaseDestroyed` (marker added when HP hits 0 so combat/tower targeting ignores it and the HUD greys out the panel), `Unit`, `Tower`, `Rock`, `Health`, `Damage`, `MoveSpeed`, `AttackCooldown`, `Armor` (timed flat damage reduction from the priest), plus the modeled-unit animation helpers (`UnitAnim` flags, `ModeledUnit` marker, `UnitAnimState` per-unit player/clip/weapon-hand state), `CombatTarget` (per-unit aggro target + last attacker, driving the march/redirect/retaliate AI), miner state (`MinerCarry`, `MinerPhase`, `MinerSlot`), `Arrow`, `Sun`, `TorchLight`/`TorchFlame`.
  - States: `GameState` (the Bevy `States` enum) and the derived `InMatch` computed state — both defined here, initialized in `GamePlugin`. The `AppSet`/`CombatSet` system sets and the `despawn_all::<Marker>` teardown helper live here too.
  - Resources: `Gold` (per-`PlayerSlot` pool), `Winner` (side that won the last finished match), `GameMode` (`OneVsOne`/`TwoVsTwo`, selected on the SideSelect screen), `GameSettings`, `SettingsTab`, `SettingsOrigin`, `MatLibrary` (the few remaining procedural meshes/materials — arrows, torches, placement ghost, and the ground material whose base-color texture is generated by `generate_ground_texture`), `EnvAssets` (glTF scene handles for the base/tower/mountain buildings and the desert props — loaded once by `load_env_assets`), `UnitModels` (per-`UnitKind` glTF model: scene, clips, weapon, built graph/nodes — loaded by `load_unit_models`), `PlacementMode`, `PlayerControllers`, `PlayerNations` (per-`PlayerSlot` chosen `Nation`, committed at launch), `MenuFocus`, `TimeOfDay`, `GameTime`, `DlssAvailable`, `RaytracingAvailable`, `AtmosphereHandle`.
  - **All tunable constants live here** (HP, damage, gold cost, speeds, ranges, geometry, animation amplitudes, day/night period). Change game balance from one place.

- **`setup.rs`** — `Startup` systems and most static scene authoring. `init_mat_library` populates `MatLibrary` (must run before anything spawns meshes — enforced via `.chain()` in `main.rs`); `load_env_assets` (also `Startup`, chained before `setup_world`) kicks off the async load of the building + desert-prop glTF scenes into `EnvAssets`. `setup_world` spawns the camera (fixed 3/4 view with `Hdr`, atmosphere, bloom, fog), the sun, the desert ground (a procedural three-region base-color texture from `generate_ground_texture` — sand play field, blue central no-man's-land, cooler decor outside, with quick smoothstep fades; the sand band is regenerated per `GameMode` in `spawn_arena` so it matches the tower-buildable zone, i.e. visible == buildable; this replaced the old white zone-marker bars), mountains, sky, and the scenery. **Scenery is procedural**: `spawn_scenery` lays a jittered grid of desert-prop `SceneRoot`s (cactus / dead tree / ruins / skull / stone / stone arch, two glTF variants each) across the background from outside the play zone out to the mountains, keeping a central gameplay rectangle clear; each cell's kind is drawn by `DesertProp::weight` (rocks/cacti/trees common, ruins/arches rare) with random yaw and per-instance scale via a tiny deterministic xorshift `Rng`. Every Meshy export is normalized to a ~1.9-unit box centered at origin, so each kind has a `*_SCALE` + `*_LIFT` (ground seat) const in `common.rs`. `spawn_arena` (`OnEnter(InMatch)`, with an existence guard for the `Paused → Settings → Paused` re-entry) builds the bases + rocks lazily at match start so the layout can reflect the chosen `GameMode` (two or four bases): `spawn_castle` spawns the `adamar_base.glb` model under the `Base` entity (rotation = `side.base_rotation()` × `BASE_MODEL_YAW_OFFSET` so the entrance faces the centre) plus corner torches; `spawn_rock` reuses the `irrhakur_stone` prop as the mining `Rock`; both the base and the rock carry a static Avian collider (`side.structure_layers()`) that blocks only enemy units (allied units pass through their own buildings, so they never get stuck on them). `spawn_torch` is the shared helper (pole + hidden flame + doused `PointLight`) used by bases and towers; the day/night `update_torches` lights them. Also hosts the Solari/DLSS sync systems (gated on cargo features), `update_torches` / `animate_sun`, the per-kind unit-model loader (`load_unit_models`) + animation-graph builder (`build_unit_graphs`), and `debug_camera_control` — a free-fly debug camera (mouse + keyboard, otherwise unused since the game is gamepad-only): hold RMB to look, WASD/Space/LShift to fly, LCtrl to boost, scroll to change speed, **R** to snap back to `CAMERA_DEFAULT_POS`. Runs in every `GameState`.

- **`units.rs`** — unit lifecycle, AI and rendering rigs.
  - **All four unit kinds (`Soldier`/`Miner`/`Archer`/`Priest`) are rigged glTF models** (Meshy exports, `assets/models/adamar/characters/adamar_<kind>_biped_Animation_*_withSkin.glb`) driven by one generalized system — there is no procedural rig anymore. `spawn_soldier`/`spawn_miner`/`spawn_archer`/`spawn_priest` all call `spawn_unit`, which spawns a `SceneRoot` child (per-kind scale + `+Z→facing` yaw correction) under an entity tagged `ModeledUnit` + `UnitAnimState`, with `Armor` (0 until buffed) and an Avian dynamic-body capsule (`RigidBody::Dynamic` + `Collider::capsule`, rotation and Y locked, `SleepingDisabled`, `side.unit_layers()`) that `combat_tick` drives via `LinearVelocity`. Per-kind glTF data lives in the `UnitModels` resource: `setup.rs::load_unit_models` loads each kind's scene (from its Walking file), one `AnimationClip` per action (the **file path is the source of truth** — Meshy scrambles internal names), and the hand weapon (`WeaponDef`); `setup.rs::build_unit_graphs` waits for each kind's clips to decode then builds its `AnimationGraph` + cached `ModelAnimNodes` (node indices + playback speeds from clip durations). `attack`/`death` are optional so the miner (walk + Heavy_Hammer_Swing only, no death clip) is handled. (Hit-reaction/"hurt" clips were removed entirely — they read poorly.) All paths/scales/yaws live in `common.rs` (`SOLDIER_*`/`MINER_*`/`PRIEST_*`/`ARCHER_*` consts).
  - `bind_unit_animation_player` attaches the owning kind's graph + `AnimationTransitions` to the scene's async-instanced `AnimationPlayer` and records it on `UnitAnimState`. `bind_unit_weapon_hand` resolves the kind's weapon bone (archer→`LeftHand`, soldier/miner/priest→`RightHand`) by walking up from the named bone to the unit root, attaches the weapon scene, and records the bone on `UnitAnimState.weapon_hand` (the archer's arrow muzzle). The `WeaponDef` transform (per-weapon consts in `common.rs`) cleanly separates the tuning knobs: `scale` (large, cancels the hand bone's ~0.007 world scale), `rotation` (Euler placement — which way the weapon points), `self_flip` (roll about its own long axis), `grip` (slide along the long axis so the hand holds an end vs the centre — 0 = centre, sign picks the end), and `offset`/`HAND_OFFSET` (nudge along the bone from wrist into the hand).
  - `animate_unit_model` runs every unit's clip state machine from `UnitAnim` (death > attack > walk > idle), tolerating missing clips. Aiming kinds (`uses_face_yaw`: archer + priest) smoothly pivot the entity toward `UnitAnim.face_yaw`; soldier/miner keep the rotation set at spawn / in `combat_tick` (the miner turns to face the rock). **Archer arrow release stays here** and is animation-driven: while aimed `combat_tick` sets `UnitAnimState.pending_shot` (the volley aim point), and `animate_unit_model` looses one arrow per shot-clip cycle (at `ARCHER_SHOT_RELEASE_FRACTION` − `ARCHER_SHOT_RELEASE_LEAD`) toward it from the weapon-hand world position. The `Archery_Shot` clip releases to the model's **left**, so when shooting `combat_tick` adds `ARCHER_SHOT_YAW_OFFSET` (−90°) to the facing. `cleanup_dead_units` holds each corpse for its kind's `death_duration` (the miner, with no death clip, holds its last pose for the generic `DEATH_DURATION` before despawning).
  - **Priest** is support-only (`Damage 0`, never targets enemies): in `combat_tick` it advances like a soldier but, when the nearest ally **ahead** is within `PRIEST_RANGE`, stops and casts (`mage_spell_cast` clip); on each cooldown tick it pushes a heal (`PRIEST_HEAL`, clamped to max) and a flat-armor buff (`PRIEST_ARMOR` for `PRIEST_ARMOR_DURATION`, refreshed each cast) for that ally. `Armor` reduces incoming damage at every site (`combat_tick` melee, `arrow_flight_system` — which also covers tower arrows) with a `MIN_DAMAGE` floor; `tick_armor_buffs` zeroes the reduction when the timer expires.
  - `combat_tick` is the heart of the game. It uses a `ParamSet` over five conflicting queries (units, bases, rocks, healths, towers) plus a disjoint `CombatTarget` query, and runs in three passes per frame: snapshot, decide, apply damage. **Soldier AI: march dead-straight toward the enemy base by default; redirect only to an enemy unit/tower that enters the short `AGGRO_RADIUS` (re-evaluated each frame → switches to a closer threat); keep chasing a committed target out to `TARGET_LEASH`; with nothing in sight, charge whoever last hit it (`CombatTarget.last_attacker`, within `RETALIATE_LEASH`); attack the enemy base on arrival (`march_dir` only steers onto the base within `BASE_SEEK_RANGE`, so units no longer converge on the centre line and pile up).** Movement is written as `LinearVelocity` (via `drive`/`face_dir`), so Avian integrates it and resolves all unit↔unit separation and blocking against enemy structures — the old manual `ally_blocking`/`allied_tower_sidestep`/`enemy_tower_blocking` hacks are gone. Archers (volley aim, below) and priests keep their own targeting but also march straight by default. **Battalion formation** is layered on the free march (no enemy target) by `formation_speed_factor` — a purely local, per-unit rule (no global controller) that scales forward speed by the *smaller* of two **graduated** slow-downs (both via `formation_slow_curve`, which fades from full speed to the `FORMATION_MIN_FACTOR` floor over `FORMATION_DECAY` — never a dead stop): (1) **rank cohesion** — a unit slows the further it has pulled ahead of nearby **same-role** peers behind it, weighted toward lateral "lane" neighbours (`FORMATION_LATERAL_RANGE`/`_FLOOR`), so each rank lines up abreast; (2) **ranged pacing** — an archer/priest eases off only as it crowds the nearest allied **soldier _ahead of it_**, keeping its per-role gap (`FORMATION_PRIEST_GAP` < `FORMATION_ARCHER_GAP`), so it paces the soldiers (never freezes) and the army self-orders soldiers→priests→archers "by range". All comparisons are bounded by `FORMATION_RADIUS`, so a far straggler never stalls the front. Units spawn in a tight column (`SPAWN_LANE_HALF_WIDTH_*`, decoupled from the wide `LANE_HALF_WIDTH_*` battlefront that still drives the tower zone + ground band) and fan out into the battalion as they advance. Damage carries its source — melee in `combat_tick`, arrows in `arrow_flight_system` — so a victim records a `last_attacker` and, when idle, charges it. Miners have their own multi-phase loop (`ToRock` → `Mining` → `Returning`) and feed `Gold` on deposit — there is no passive income.
  - **Volley archery + physical arrows.** `combat_tick` aims each archer at `volley_aim` — the centroid of the densest knot of enemy units within `ARCHER_RANGE` (for each enemy it counts neighbours within `VOLLEY_RADIUS`, takes the densest; falls back to the nearest enemy structure). `animate_unit_model` looses one arrow per shot cycle toward that ground point. The arrow (`spawn_arrow` + `arrow_flight_system`) is a dumb scripted parabola with **no homing and no attached target**; each frame `arrow_flight_system` tests its position against enemy colliders via `SpatialQuery::shape_intersections` (filtered by `side.arrow_target_mask()` — so no friendly fire, and the arrow needs no collider of its own). On the first enemy hit it deals damage (armor + `MIN_DAMAGE` floor) and records the shooter as that victim's `CombatTarget.last_attacker` (ranged retaliation); if it reaches the ground untouched it plants (`Arrow.stuck`) and ages out over `ARROW_STICK_DURATION`.
  - `process_damage_effects` and `cleanup_dead_units` close the loop.

- **`towers.rs`** — tower entity construction and aiming (`tower_attack_tick`, `cleanup_dead_towers`, validity helpers `is_valid_tower_zone` and `collides_with_existing_tower`). `spawn_tower` spawns the `adamar_tower.glb` model (from `EnvAssets`) under the `Tower` entity plus one `spawn_torch`; the model child carries the side mirroring + `TOWER_MODEL_YAW_OFFSET` so the tower faces the centre, while the entity itself stays unrotated so aiming/arrow spawns are unaffected. The `Tower` entity also carries a static Avian collider (`Collider::cylinder` + `side.structure_layers()`) that blocks enemy units (allied units pass through; this replaces the removed manual sidestep and the defensive block is what matters). Each side may only build inside its own zone, defined by `ZONE_BOUNDARY` in `common.rs`. `is_valid_tower_zone` also takes `GameMode` so the Z bounds match the active lane layout (tighter in 1v1, wider in 2v2).

- **`healthbar.rs`** — billboarded health bars over units, towers and bases. All bar meshes/materials are shared via the `HealthBarAssets` resource (built once by `init_health_bar_assets` at startup: two width variants + a `FILL_STEPS` green→red material ramp), so spawning a bar allocates no assets. `spawn_health_bar_for_{unit,tower,base}` are called by each spawner; `update_health_bars` positions and billboards (Y-axis only) every frame, but rescales the fill and re-tints (by swapping to the nearest ramp material — never mutating a material asset) only when the HP fraction changes. Bars whose owner has despawned clean themselves up.

- **`game.rs`** — `GamePlugin`: owns the `GameState`/`InMatch` state machine and the per-match resources (`Gold`, `GameMode`, `Winner`). `check_winner` (only while Playing) marks dead bases with `BaseDestroyed`, and once ALL of a side's bases are down sets `Winner` and transitions to `Ended`. `reset_match` (OnEnter(Menu)) despawns every `BattlefieldEntity` (a bundled `Or<…>` filter) and resets gold, placement, pad mapping, winner **and `GameTime`/`TimeOfDay`** so a relaunched match starts at the same morning; it also fires harmlessly on the initial Menu entry at boot.

- **`graphics.rs`** — settings UX backend (no UI nodes here).
  - `GraphicsPreset` (Low/Medium/High/Ultra/Custom) — `apply` only touches quality fields (raytracing, dlss, taa, bloom, atmosphere, volumetric_fog, distance_fog), display fields (fullscreen, vsync, hdr, tonemapping) are preserved as user prefs. `Custom` is **derived**, never selected: `update_graphics_preset` runs `detect` whenever settings or DLSS availability change.
  - `ParamId` + `MenuSlot` + `tab_slots(tab)` — single source of truth for "which slots live on which tab and in what order". `ui.rs` builds buttons by iterating this; `settings_input_system` matches on the slot at the focused index. Adding a parameter means editing both `ParamId` and the tab arrays.
  - `param_description` returns functional + technical text + per-resource `Impact` (None/Low/Medium/High). Use `Impact::None` (renders as "none") for parameters with no measurable cost.
  - `load_settings` / `save_settings` / `persist_settings` — flat `key = value` text file, sanitised against missing build features on load.

- **`music.rs`** — `setup_music` spawns a paused looping `AudioPlayer<AudioSource>` tagged `GameMusic`. `sync_music_playback` calls `sink.play()` only while `GameState::Playing` (Paused, Menu, Settings, SideSelect, Ended all keep it silent). Also reacts to `Added<AudioSink>` so playback starts the moment the file finishes loading.

- **`ui.rs`** — every Bevy UI node lives here, plus the per-state input systems.
  - `setup_ui` builds the persistent HUD (top: in-game clock; bottom corners: one panel per `PlayerSlot` with the unit/tower buttons, the base HP readout and the gold counter). In 2v2 the top corners host the second pair of player panels.
  - State overlays: `spawn_{menu,pause,sideselect,endgame}_overlay` run on `OnEnter` of their state and `despawn_all::<Marker>` tears them down on `OnExit` (despawn is implicitly recursive — Bevy 0.18 relationships — so removing the root removes the children). Two in-state refreshers run in `AppSet::React`: `refresh_pause_overlay` (rebuilds on `PlayerControllers` change so a pad disconnect mid-pause refreshes the warning lines) and `update_settings_overlay` (builds on entry via the `State` resource's change flag, rebuilds on tab change or a STRUCTURAL slot-list change — plain toggles are reflected in place by the label/description systems). HUD visibility and per-pad `PlayerFocus` follow `InMatch`: `show_game_hud`/`grant_player_focus` on enter, `hide_game_hud`/`revoke_player_focus`/`clear_placement` on exit.
  - Settings overlay is the most involved: a two-column layout (menu column + description card) with a tab strip (Video/Graphics) at the top, switched with LB/RB. Background is translucent so live setting changes are visible behind the menu. Description text is populated at spawn and refreshed by `update_settings_description` on `MenuFocus`/`SettingsTab`/`GraphicsPreset` change.
  - Input systems: `menu_input_system`, `endgame_input_system`, `sideselect_input_system`, `pause_input_system`, `settings_input_system`, `gameplay_input_system`, `placement_system` — one per state, gated with `run_if(in_state(..))` and writing transitions through `NextState<GameState>`; since transitions apply between frames, the new state's system never sees the activation press.
  - **SideSelect flow** (`sideselect_input_system` + `update_sideselect_cards`): each pad's `SeatSelection` advances through `SeatPhase::PickingSeat` → `PickingNation` → `Locked` (A confirms, B steps back; B in PickingSeat leaves entirely). A pad reserves its slot from `PickingNation` on (`claims_seat()`), so others can't take it. Start launches only when ≥1 pad is `Locked` and none is still mid nation-pick; the commit writes `PlayerControllers` + `PlayerNations` per locked slot. Each card shows three lines via one `SideCardLine{slot, line}` marker (`CardLine::Controller`/`Status`/`Nation`): the controller's `Name` (gamepad entities carry a `Name`), the status, and the chosen nation.
  - `apply_graphics_settings` is the bridge from `GameSettings` back to the camera / window. It inserts or removes per-camera components (`Hdr`, `Bloom`, `Atmosphere`, `VolumetricFog`, `DistanceFog`, `TemporalAntiAliasing`) and mutates `Window.mode` / `Window.present_mode` / `Tonemapping`. Raytracing/DLSS toggling lives in `setup.rs` (feature-gated).

### Conventions and Bevy 0.18 specifics

- Gameplay systems are gated `run_if(in_state(GameState::Playing))`; on `OnExit(GameState::Playing)`, `freeze_units` zeroes every unit's velocity/anim flags and Avian's `Time<Physics>` is paused — so pause/end-game freezes movement, income, combat and music. Asset-binding systems (`build_unit_graphs`, `bind_unit_*`) and corpse cleanup stay ungated.
- Camera setup pattern: `Camera3d::default()` + `Hdr` marker (`bevy::render::view::Hdr`) — HDR is no longer a field on `Camera`.
- Use `Camera3d` / `Mesh3d` / `MeshMaterial3d` component pattern (no bundles). Ambient light is configured via the `GlobalAmbientLight` resource (the per-camera `AmbientLight` component overrides it).
- `Time::delta_secs()` (not `delta_seconds`) for f32 delta time in this Bevy version.
- `Msaa::Off` is required wherever the deferred renderer is active (Solari forces deferred globally; TAA also forces MSAA off).
- Audio: `AudioPlayer<AudioSource>` is the spawnable component; the `AudioSink` component is added **asynchronously** by the audio backend once the source decodes — systems that pause/resume must tolerate the sink being absent for the first few frames.
